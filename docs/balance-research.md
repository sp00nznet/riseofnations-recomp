# Rise of Nations: Extended Edition: balance complaints mapped to data

Research date: 2026-11-18. Install read (read-only): `E:/SteamLibrary/steamapps/common/Rise of Nations/Data`.
Nothing in the install was modified. The house rules below are proposals for an opt-in override layer. None are implemented.

## Caveats

- **The web research was thin.** Steam community pages kept returning HTTP 429, TV Tropes returned 403, and the mhloppy.com CBP notes page returned 404. No r/riseofnations thread could be read directly. The "how widely reported" column means "how many independent threads I could actually read", so it does not reflect real prevalence. Where a claim comes only from a search-result snippet, it is marked **(unverified)**.
- **Bedouins are not a nation in RoN or T&P.** `grep -i bedouin` over all of `Data/` finds nothing. The 24 nations are the 18 base nations plus Americans, Dutch, Indians, Iroquois, Lakota and Persians. The Bedouin complaint is dropped. Players may mean Nubians or Turks.
- **Most opinion threads are old.** The Heaven Games tier thread dates from 2011-12 and the Steam threads from 2014-16. Both sides argue in them: some say "nations are fine", others say "X is broken". Neither is a consensus.
- **A data edit touches every game.** The game reads these XMLs for single player and multiplayer alike, so an opt-in house rule needs a mod folder or Workshop-style override, or a recomp-side switch. Editing `Data/` in place would desync multiplayer against stock clients.

## Background: the EE damage-table bug (the community's #1 issue)

The Community Balance/Bugfix Patch (CBP, by MHLoppy, Steam Workshop [2287791153](https://steamcommunity.com/sharedfiles/filedetails/?id=2287791153)) exists mainly because EE broke the damage multipliers. According to the search snippet, about 28,677 damage modifiers are wrong, so all units deal or take the wrong damage compared to T&P, and EE's armor templates are also broken. See the [CBP Steam thread](https://steamcommunity.com/app/287450/discussions/0/4578439633204583973) and the [smods mirror](https://catalogue.smods.ru/archives/265944). The thread itself names no units; it points to a video and spreadsheet I could not open.

- **Where it lives:** `balance.xml` holds 291 `<ENTRY name="Attacker" Target="pct" ...>` rows. Most cells are `100`.
- **Example:** `Anti-Aircraft_Missile` has `Bomber="75" Strategic_Bomber="75" Lancaster_Bomber="75" Fighter_Bomber="90"`.
- **Status:** I did not verify whether the EE bug lives in this table or in code that reads it. If it is in code (the snippet's wording, "a workaround", suggests a code or engine-side bug), a data patch can only compensate for it, as CBP does.
- **Last CBP release:** the community spreadsheet lists Alpha 9c as the last release, with no further updates planned **(unverified, search snippet)**.

## Can't be done by data alone (needs code)

- **The EE damage-table bug itself.** If the root cause is in code, `balance.xml` can only compensate for it, as CBP does. This is unverified, and it is the most important thing to settle next. One way to settle it is to read in the recomp how `balance.xml` gets parsed and applied.
- **Partial Missile Shield interception, and how often the AI decides to fire nukes.**
- **The American instant-wonder power and the Lakota build-anywhere / no-houses power.** I found no XML constant for either.
- **Rules scoped to one game mode** (for example a Lakota nerf in nomad only), and **any opt-in toggle**. The game has no layer for "house rules on, stock rules off"; it reads the files it is given. Shipping these as opt-in needs a separate mod data folder, or a recomp switch that loads an override set. Either way, everyone in a multiplayer game must use the same set.
